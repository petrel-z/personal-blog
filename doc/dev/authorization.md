# 后台权限修复与上线说明

后台 API 现在在解析请求体、读取管理数据或执行写入前，检查当前会话、账号是否存在/被删除，以及数据库中的角色权限。匿名或失效身份返回 HTTP 401 / 业务码 4010；权限不足返回 HTTP 403 / 业务码 4030。权限查询故障时拒绝执行并返回 500。

## 管理员初始化（上线前执行）

本次本地只读检查发现 Role 表为空。没有自动授予任何账号权限，也没有修改数据库。

1. 确认 `.env` 的 `DATABASE_URL` 指向希望配置的数据库，并设置 `AUTH_URL` 为实际访问地址（本地例如 `http://localhost:3000`，生产使用站点真实域名）。当前 Auth.js v5 在生产模式下仅设置 `NEXTAUTH_URL` 仍可能报 `UntrustedHost`，导致会话无法解析；示例配置已改用 `AUTH_URL`。
2. 准备一个已注册、未删除的博主账号。
3. 明确指定该账号邮箱执行：

```bash
pnpm auth:setup --admin-email '博主已注册的邮箱'
```

命令在一个事务中创建缺少的角色/权限，并只给指定账号关联 admin。可重复运行；不重置密码，不删除已有自定义授权，不自动提升第一个注册者或所有用户。参数缺失、账号不存在或已删除时不写入任何权限。已有 admin 角色的账号直接拥有全部管理权限，无需等待权限表回填。发布代码前先运行初始化，可避免现有博主因没有角色而无法访问后台。

仅查看用法（不连接数据库、不写入）：`pnpm auth:setup --help`。

## 默认权限

| 角色 | 能力 |
| --- | --- |
| admin | 全部管理操作，包括跨作者文章管理 |
| editor | 仪表盘、自己的文章读取/创建/修改/删除、图片上传；不含发布权限 |
| reviewer | 仪表盘、评论读取、通过、拒绝；不含评论删除 |
| member | 无后台管理权限，公开注册仍获得此角色 |

其他角色通过现有 RolePermission 关联授予权限。每个管理请求从数据库读取最新授权，撤销角色或权限后，旧 JWT 不会继续赋予管理能力。删除账号后也不能重新登录。

## 接口边界

- 文章 POST/PATCH/DELETE：分别需要 post:create、post:update、post:delete；非管理员只能修改/删除自己的文章。
- 创建已发布文章、将草稿发布、修改已有已发布内容：额外需要 post:publish。
- 删除使用独立的 post:delete 权限：编辑者可删除自己的文章，包括已发布文章；编辑已发布内容仍需要 post:publish。
- `/api/posts?scope=admin`：需要 post:read，返回管理列表（含草稿）；非管理员仅返回自己的文章。公开查询默认仅返回已发布文章。显式查询非公开状态也要求权限。
- 文章详情：公开文章可匿名访问；草稿/归档预览需要 post:read 和文章归属权限；删除的文章返回 404。
- 分类、标签写操作：category:manage、tag:manage。公开分类/标签读取继续可用。
- 保存文章时，没有 tag:manage 的账号只能关联已有标签；提交新标签名会拒绝整个保存操作，避免通过文章接口间接创建标签。
- 后台评论列表/单条评论详情：comment:read。通过、拒绝、删除分别使用 comment:approve、comment:reject、comment:delete。
- 敏感词管理：sensitive-word:manage；设置写入：settings:update；用户列表：user:read；审计日志读取：audit:read；上传：upload:create。
- `/api/audit-logs` 不再提供 POST；业务服务使用已验证的操作人写入日志，客户端不能自行提交审计身份。
- 管理 API 强制动态执行，身份相关响应使用 `Cache-Control: private, no-store`。
- 后台布局在服务端拒绝游客/无管理权限账号；前端按权限控制导航、页面和操作按钮。API 仍是最终的访问控制边界。


回归测试调用真实 Route Handler 和文章业务服务，仅替换会话、数据库和存储边界；覆盖匿名/成员拒绝且无写入、授权操作、撤权与删除账号、跨作者访问、发布权限、并发状态变化、标签创建权限、公开读取以及初始化账号限制。CI 已配置执行这组测试。

实际部署应在独立测试数据库使用游客、成员、编辑、管理员账号做一次 HTTP 联调，再运行上述初始化和发布流程。依赖安全升级、公开评论字段过滤和其他审核发现不属于本次权限修复。
